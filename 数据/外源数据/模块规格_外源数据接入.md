## 1 模块职责

把一批政务记录补充为「带地理位置」的记录，并产出行政区划到位置的映射。

| 项 | 内容 |
|---|---|
| 输入 | 记录集合：`表名 / 记录ID / 名称 / 区县 / 街道或地址` |
| 输出 1 | **坐标长表**（资产一同构）：每条记录一行，含坐标、精度等级、可信标记、不可信原因 |
| 输出 2 | **行政区划映射表**（资产二同构）：`(区县, 行政区划) → 中心坐标` |
| 输出 3 | **接入状态**：`成功 / 弱定位 / 失败`，供下游决定是否参与距离判定 |
| 输出 4 | **行政区划属性**：`高德区县 / adcode / 乡镇街道`，两侧同构，供 `poi_district_match`、`street_match` 使用 |
| 不做 | 不提供标签、不反推对端、不修改原始记录、不修改已冻结坐标 |

## 2 接口契约

```python
class ExternalGeoEnricher:
    """外源地理补全器。所有输出必须可缓存、可断点续跑、可离线复现。"""

    def __init__(self, key: str, cache_dir: str,
                 qps_interval: float = 0.30,
                 hard_timeout: float = 8.0): ...

    # ---- 原子接口 ----
    def geocode(self, address: str, city_adcode: str | None = None) -> GeoHit | None:
        """地址 → 坐标。city_adcode 决定跨省错配率；缺省会落到外省已验证。"""

    def regeo(self, lng: float, lat: float) -> PointAdmin | None:
        """坐标 → 行政区划（district / township / adcode）+ 规范地址。

        现在**是资产生产接口**：房交侧的 高德区县 / adcode / 乡镇街道 由本接口产出。
        仅当坐标是业务坐标（面坐标质心）时使用；不要用地址地理编码点代替业务坐标。
        """

    def districts(self, keywords: str, subdistrict: int = 1) -> list[District]:
        """区县 → 下级行政区划列表（含 name/adcode/level/center）。"""

    # ---- 组合接口 ----
    def enrich(self, records: list[dict], name_field: str,
               area_field: str, street_field: str) -> pd.DataFrame:
        """批量补全，返回资产一同构的 DataFrame。"""

    def build_admin_table(self, areas: list[str]) -> pd.DataFrame:
        """批量构建行政区划映射，返回资产二同构的 DataFrame。"""

    def admin_of_points(self, points: list[tuple[str, float, float]]) -> pd.DataFrame:
        """批量坐标 → 行政区划属性。用于房交侧补全（§3.6）。"""

    # ---- 判定 ----
    def is_trusted(self, hit: GeoHit | PointAdmin, area_name: str,
                   side: str) -> tuple[bool, str]:
        """两级可信判据，`side ∈ {property, transaction}`。返回 (是否可信, 不可信原因)。"""
```

`GeoHit` 至少含：`lng, lat, level, adcode, district, formatted, query`。
`PointAdmin` 至少含：`district, township, adcode, formatted, location`。

**两条硬性契约**

1. `regeo` 的结果写入资产时，必须同时写入 `行政区划来源`，取值 ∈ `{业务字段+地理编码, 逆地理编码(质心), 未解析}`；
2. 任何一次资产生成都必须落 `manifest`（输入/输出 SHA-256、调用次数、方法、时间），缺失即视为不可复现。

## 3 必须实现的工程要求

**以下每一条都来自实测失败，不是理论推测。** 缺任何一条都会导致结果错误或流程卡死。

### 3.1 网络层

| # | 问题 | 现象 | 方案 |
|---|---|---|---|
| 1 | `urllib` 的 `timeout` **不覆盖 DNS 解析阶段** | DNS 卡住时进程无限等待（曾挂死 36 分钟，CPU 仅用 25 秒） | 每个请求放进 **daemon 线程**，`thread.join(timeout)` 硬超时；超时即放弃并把线程留作 daemon |
| 2 | DNS 可能返回假 IP 并失效 | 解析到 `198.18.0.x`（代理层）后请求挂死；某次切换后变成真实 IP `106.11.28.33` | 缓存 `getaddrinfo` 结果；连续失败 2 次即 `clear_dns_cache()` |
| 3 | Windows 下 `curl.exe` 不可用 | `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)` | **只能用 Python `urllib`**（OpenSSL 栈） |
| 4 | 部分抓取工具会拒绝该域名 | `web_fetch` 报 "resolves to a non-public IP address" | 同上，走 Python |
| 5 | 瞬时错误码需要重试 | `10021`（QPS 超限）929 次、`30001`（引擎异常）609 次 | 建立 `TRANSIENT = {10021, 30001, 10004, 10022, 10029, 30000}`，退避重试 + 自适应降速 |
| 6 | **不复用连接会慢 20 倍** | `urllib` 每次新建 TLS：**5.04 s/次**；`http.client` keep-alive：**0.26 s/次** | 长连接单连接串行调用（本模块单线程，足够 4 QPS）；不要用 `urllib.request.urlopen` 逐条打 |

#### 3.4.1 资产二的结构性缺陷（必须知道）

资产二的 `区县` 列语义是**"以该区县为 keywords 查询时返回的下级列表"**，不是行政归属。因此：

| 现象 | 数据 | 处理方式 |
|---|---|---|
| `渝北区` 只剩 2 行、`江北区` 0 行 | 两区的街道全在 `两江新区`(43 行) 下 | 不改归属；查 `两江新区` 节点 |
| `高新区` 0 行 | 其街道挂在 `沙坪坝区`/`九龙坡区` 下（虎溪/西永/曾家/香炉山、金凤/白市驿/走马/含谷/巴福） | 用**代管映射表**解释，不改归属 |
| `北碚区` 17 行，含 `兴隆镇`/`统景镇`；`渝北区` 也有这两行 | 归属存疑（两江代管区域） | 以 regeo 的 `(district, township)` 为权威键校准，不直接改写 |
| 8 条 `兜底` 行含 `汉渝路街道`/`西南政法大学`/`两江投代管` | 非行政街道单元 | 保留但标 `级别=兜底`，**不得**当作街道名做精确匹配 |
| query 侧街道名 8,518/8,782（97.0%）能在此表按 `(区县, 名称)` 找到 | 未命中的 264 条集中在北碚区 132、九龙坡区 110 | 剩余 3.0% 用**全局名称匹配 + 代管映射**兜底，不按区县限定 |

**结论：资产二不需要重新拉取 API，它缺的不是数据，是"归属语义"。** 归属语义由两处承担：功能区代管并入 `_area_equivalent` 的别名表（唯一来源），层面归属以 regeo 的 `(district, township)` 为权威键。本次只做两件事：加 `规范名`（去 `街道办事处/街道/镇/乡` 后缀）、保留 `级别=兜底` 标记；残留冲突进 `review_needed.csv` 人工复核。

### 3.5 坐标与可信判定

| # | 问题 | 现象 | 方案 |
|---|---|---|---|
| 21 | 房交坐标是 **CGCS2000/WGS84**，高德是 **GCJ-02** | 原始中位距离 576 m；转换后 249 m；<100 m 样本从 **0 → 20** | 距离计算前必须 `wgs2gcj()`（本地实现，不用配额） |
| 22 | **`level` 单独不可信** | `level=住宅区` 也可能在**新疆伊宁**（`建银小区`）、**澳门**（`福康大厦`） | **两级判据**：① level 白名单 ② 高德区县 与登记区县一致（含别名/等价类/功能区） |
| 23 | 面坐标几何损坏 | 113 条包围盒对角线 ≥1000 m（最大 171 km），质心不可信 | 包围盒对角线 ≥1000 m 判为不可信 |
| 24 | 只查 level 可信率虚高 | 84.2% → 加区县一致性后 **78.7%** | 必须两级都过 |
| 25 | **房交坐标的实际口径** | 2026-11-24 复核：资产一房交坐标 = `wgs2gcj(面坐标全部顶点均值)`，3,260 行逐行 **0.0 m** 误差 | 坐标已冻结，**不得改动**；需要行政区划时直接对该坐标做 regeo |
| 26 | 面坐标几何对质心的影响 | 530/3,260（16.3%）是多面；36 行包围盒 >1 km²；4 行离谱（最大 163 km × 53 km，与面积加权质心偏 94.5 km） | 99% 的行"顶点均值 vs 面积加权质心"差 <460 m，**不必全量重算**；仅对包围盒对角线 ≥1000 m 的 113 行用"最大面面积加权质心 + wgs2gcj"重算，且只用于行政区划查询，不回写坐标 |

### 3.6 房交侧行政区划补全

#### 3.6.1 为什么不能用地址补

房交表 `街道` 列不存在、`高德区县` 全空（0/3,260），但 `地址` 100% 有值。看似可以用地址补，实测都不成立：

| 方案 | 实测结果 | 结论 |
|---|---|---|
| 地址 → 地理编码 → 坐标 → regeo | 50 条样本 **11 条落错区县**，最远偏 **257 km**（涪陵→潼南、南川→梁平）；加区县前缀虽纠回区县，但 level 掉到 `乡镇` | **不能用**。地址短、重名多，`city` 不约束 |
| 地址文本 + 名录最长匹配 | 全库覆盖 919/3,260 = **28.2%**；878 条金标准上覆盖 256、正确 233 = **91.0%** | 只能做"有则用"的补充，不能当主来源 |
| 最近街道中心（资产二中心点） | top-1 仅 **44.6%**；到中心中位距离 **2.5 km** | **不可用**，会注入一半以上错误 |
| **坐标 → 逆地理编码 → township** | 878 条实测：`township` 100% 落在行政区划名录内；`district` 与业务区县严格一致 764/878，别名等价后 **841/878 = 95.8%** | **采用**。坐标是业务面坐标质心，语义就是"小区所在地" |

#### 3.6.2 协议

```
对每条房交记录 r：
  loc = (r.经度, r.纬度)                      # 已冻结的 GCJ-02 质心，不改动
  resp_base = regeo(loc)                     # /v3/geocode/regeo，extensions=base
  若 r.面坐标包围盒对角线 ≥ 1000m:            # 113 行
        loc_fix   = wgs2gcj(最大面面积加权质心)
        resp_fix  = regeo(loc_fix)           # 多取一次，只用于区划
  择优：若 resp_fix 区县 ≡ 登记区县 且 resp_base 区县 ≢ 登记区县 → 用 resp_fix，来源记 "逆地理编码(最大面质心)"
        否则 → 用 resp_base，来源记 "逆地理编码(质心)"
  r.乡镇街道   = resp.addressComponent.township
  r.高德区县   = resp.addressComponent.district
  r.adcode     = resp.addressComponent.adcode
  r.规范地址   = resp.formatted_address
  r.定位方式   = "面坐标质心"                  # 与 query 侧 "高德地理编码" 区分
可信判定（房交侧）：
  可信 = 坐标在重庆 bbox 内 AND 面坐标包围盒对角线 < 1000m AND 高德区县 ≡ 登记区县
  # 房交侧没有 level（不是地理编码），因此 level 白名单一项记 N/A，不得按"缺失即通过"处理
  # 物业处侧沿用原冻结判据，不重判
```

**取值清洗**：`township` 可能为空（山区/边界点）→ 保留空并记 `未解析`；`district` 可能与登记区县不一致（两江/高新/跨江）→ 保留高德值，用等价表解释，不覆盖。

## 4 可信判据（必须实现）

```
可信(物业处) = (level ∈ {住宅区, 兴趣点, 门址, 门牌号, 单元, 商务大厦})
             AND (高德区县 ≡ 登记区县)
             AND (坐标在重庆辖区 bbox 内)

可信(房交)   = (坐标在重庆辖区 bbox 内)
             AND (面坐标包围盒对角线 < 1000m)
             AND (高德区县 ≡ 登记区县)          # 由 §3.6 regeo 提供
             # level 不适用（房交坐标非地理编码），记 N/A
```

区县"一致"包含三类等价，缺一即误判：

| 类型 | 例 |
|---|---|
| 别名 | 石柱县 ≡ 石柱土家族自治县；酉阳县 ≡ 酉阳土家族苗族自治县；秀山县 ≡ 秀山土家族苗族自治县；彭水县 ≡ 彭水苗族土家族自治县 |
| 等价类 | **两江新区 ≡ 渝北区 ≡ 江北区 ≡ 北碚区**（用户确认，且高德区划模型亦如此） |
| 功能区代管 | 高新区 ≡ 沙坪坝区/九龙坡区；经开区 ≡ 南岸区；万盛区/万盛经开区 ≡ 綦江区；双桥经开区 ≡ 大足区；蔡家岗街道、童家溪镇 行政属北碚区，实际由两江新区直管 |

> 2026-11-24 实测：补上「酉阳/秀山/彭水」三个自治县简称后，房交侧区县冲突从 96 条降到 **30 条**（其中 21 条是登记区县为空），即真实冲突仅 **9/3,260 = 0.3%**。别名表是唯一来源：`code/er/geo_asset.py::_area_equivalent`，任何脚本不得另抄一份。
> `经开区` 原映射为 `巴南区`，本次 regeo 有 12 条落在 `南岸区`，已改为 **南岸区**（重庆经开区实际位于南岸区）。

## 5 已知的非文档化 API 行为

| 行为 | 说明 |
|---|---|
| 地理编码一次返回多候选 | 按 `level` 优先级取最优：`住宅区 > 门牌号 > 门址 > 兴趣点 > 单元 > 道路 > 区县` |
| `level` 取值 | 实测出现：`住宅区 / 兴趣点 / 门址 / 门牌号 / 单元 / 乡镇 / 村庄 / 道路 / 区县 / 省 / 公交地铁站点 / 未知` |
| **地理编码不返回街道** | `geocodes[].township` 恒为 `[]`；只有**逆地理编码**的 `addressComponent.township` 才是行政街道 |
| **逆地理编码有 township** | `addressComponent = {district, township, adcode, towncode, streetNumber{street,number}}`；这是房交侧补 `street` 的唯一权威来源 |
| `city` 参数是提示 | 不构成过滤；`city=经开区` 会返回长春宽城区（见 §3.3 #12） |
| 区划接口一次返回整区县下级 | 1 次调用可覆盖 20~52 条街道记录，不必逐街道查 |
| 区划有生效日期 | 永昌街道 **2025-12-24** 由中山路街道拆分设立；物业处数据（`gmt_create` 2025-11-05）早于拆分，两边都对但时点不同 |
| 房交「点位坐标」不是点 | 是线段/边界顶点（12% 含多个点），不能当定位点用；本次也不使用它 |
| 逆地理编码无批量接口 | 必须逐点调用；`/v3/geocode/regeo` 一次一个 `location` |
| **空字段占位是 `[]` 而不是空串** | regeo 在部分边界点返回 `district: []` / `township: []`，直接 `str()` 会得到字符串 `"[]"`，比空值更难排查 | 入库前统一清洗：`"[]" / "[ ]" / "-" / "None"` → `""`，并计入 `未解析` |
