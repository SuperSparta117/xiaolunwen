# 外源数据资产说明

本目录的规范资产是两个 CSV：`asset1_poi_coord.csv`（两侧坐标与行政区划属性）、`asset2_admin_geo.csv`（行政区划 → 中心坐标）。另有金标准 `数据/A_mission_匹配映射_v2.csv`。

字段定义只在本文件维护；接口调用、可信判定规则、补全协议与复现步骤见 [`模块规格_外源数据接入.md`](模块规格_外源数据接入.md)。

## 1.3 房交侧行政区划属性

房交表没有街道字段，坐标来自原始面坐标质心而不是地理编码，因此 `高德区县 / adcode / level` 三列原先恒空。补全方式是**对已冻结的面坐标质心做逆地理编码**，**坐标一个都没有改**：

| 项 | 结果 |
|---|---|
| `乡镇街道` | 3,260/3,260 非空（regeo `township`，行政街道） |
| `高德区县` | 3,260，与登记区县别名等价率 99.1% |
| `adcode` | 3,260 |
| `规范地址` | regeo `formatted_address` |
| `可信`（房交口径） | 3,122/3,260 = 95.8%（bbox + 面坐标对角线 <1000m + 区县等价；level 项不适用） |
| `经度` / `纬度` | 未改动，与补全前逐行一致（12,042/12,042） |

- 原始响应：`regeo_fangjiao.jsonl`（3,373 条，其中 878 条为既有响应）
- 113 条面坐标包围盒对角线 ≥1000m 的记录额外用「最大面面积加权质心 → wgs2gcj」补算一次区划，仅 1 条因此改判
- **878 条既有 regeo 响应来自 `raw_cache.zip`**，当年用于坐标系判定与金标准复核，且 878/878 都是 gold candidate

# 2 资产二：`asset2_admin_geo.csv`

**行政区划 → 物理位置**。街道/镇/乡是**行政单元**，本身不是地名，作为文本无地理含义；本表把每个行政单元映射为它的中心坐标。

| 项 | 值 |
|---|---|
| 行数 | 1,094 |
| 覆盖区县 | 40 |
| 全部有中心坐标 | 1,094 |
| 坐标系 | GCJ-02 |
| 采集时间 | 2026-11 |

## 2.1 字段

| 列 | 说明 | 来源 |
|---|---|---|
| `区县` | 所属法定区县 | 源数据 |
| `区县adcode` | 高德行政区划代码 | 行政区划查询 |
| `行政区划` | 街道 / 镇 / 乡 名称 | 行政区划查询 |
| `级别` | `street`（1,086）/ `兜底`（8，区划树缺失时用地理编码补中心点） | 行政区划查询；兜底行由地理编码补 |
| `查询串` | 实际发出的请求（区划接口按区县聚合，兜底行为地址串） | 本地拼接 |
| `接口` | 实际调用的接口 | `行政区划查询` / `地理编码` |
| `中心经度` / `中心纬度` | 行政区划的行政中心 | 行政区划查询 · `center`；兜底由地理编码取点 |
| `数据来源` | 记录该行来源 | 本地标记 |
| `规范名` | 去 `街道办事处/街道/镇/乡` 后缀的可比键 | 本地派生 |
| `是否标准行政名` | 名称是否以 `街道/镇/乡` 结尾 | 本地派生 |
| `坐标系` / `采集时间` | 常量 | — |

## 2.2 覆盖率

- 8 条 `兜底` 行是区划树缺失的单元（如渝北区统景镇），清单见规格 §3.4；
- 物业处 355 个 `(区县,街道)` 组合 → **100%** 命中；
- 征收处 998 个组合 → 935 同区县命中 + 63 经父区命中，**0 未匹配**。

> 中心点不等于辖区范围、区划有生效日期等已知局限见规格 §3.4/§5。

# 3 金标准：`A_mission_匹配映射_v2.csv`

外源坐标除了增强特征，还用于**复核和补全任务 A 的金标准**。本节固化其构成与复核结论。

## 3.1 构成

| 项目 | 数量 | 来源 |
|---|---|---|
| 初始标注 | 2,709 对 | 按「小区名 + 区县」精确一致生成 |
| 外源坐标补全 | 317 对 | 坐标距离判定（同名/异名 + 坐标重合） |
| **合计** | **3,026 对** | |

补全的 317 对按判据分为四类：

| 类型 | 数量 | 判据 | 置信度 |
|---|---|---|---|
| 同名 + 坐标重合 | 206 | 名称完全一致，距离 ≤ 120 m | 高 |
| 同名 + 邻近 | 60 | 名称完全一致，距离 120–400 m | 中 |
| 同名 + 对端已占用 | 36 | 名称完全一致，对端已被另一条房交记录占用（多对一） | 高 |
| 名称变体 + 坐标重合 | 15 | 名称有前后缀/分隔符差异，距离 ≤ 120 m | 高 |

补全后覆盖率：房交侧 82.98% → **92.70%**，物业处侧 30.85% → **32.83%**。

金标准本体在原 8 列之外增加 `source`、`confidence`、`distance_m`、`name_sim`、`note` 五列：`source` 区分初始标注与外源补全，`distance_m` 记录坐标距离证据，`note` 记录经复核确认的 87 条对的处理结论。评测时可按 `source` 分层报告。

## 3.2 复核结论

对 878 条「距离矛盾或偏大」的对逐条做了逆地理编码复核，**结论是 0 条标注错误**，全部为坐标或编码问题：

| 复核结论 | 数量 | 占比 | 成因 |
|---|---|---|---|
| 区县完全一致 | 685 | 78.0% | 物业处正向地理编码跑偏，标注正确 |
| 功能区 ↔ 法定区口径差异 | 106 | 12.1% | 两江新区 ≡ 渝北/江北；蔡家岗、童家溪属北碚但归两江直管 |
| 区县一致、街道不同 | 79 | 9.0% | 街道/镇是**行政单元**而非地名；或区划调整的时点差异 |
| 区县确实不一致 | 8 | 0.9% | 经人工判断，仍有 7 条为坐标不可信、1 条存在真实二义性并被确认保留 |

## 3.3 口径约定

- 街道/镇/乡**不作为文本特征**使用。它们是行政单元，文本本身不携带地理含义，只用于候选阻断与一致性校验；其地理含义通过资产二的中心坐标获得。
- 区县"一致"的判定（别名、等价类、功能区代管三类）见规格 §4；缺任一条都会把正确配对误判为冲突。
- `street_match` 是**行政区划一致性**（同一街道/镇/乡），不是文本相似度；负例中同街道比例高是正常的（困难负例本就同街道不同小区），该特征必须与名称、距离联合使用。

`raw_cache.zip` 与 `regeo_fangjiao.jsonl` 是复现与审计的唯一依据——图商返回结果会随时间变化，没有原始响应就无法证明资产是怎么来的。
