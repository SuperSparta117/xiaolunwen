# 1 使用了哪些高德 API

## 1.1 接口清单

Key 类型为高德开放平台的 **「Web 服务」**（不是 Web端 JS API / Android / iOS）。实际调用三个接口：

| 接口 | 端点 | 调用次数（去重后） | 是否写入资产 |
|---|---|---|---|
| **地理编码** | `GET https://restapi.amap.com/v3/geocode/geo` | **14,985** | ✅ 资产一的坐标、level、adcode、规范地址、高德区县 |
| **行政区划查询** | `GET https://restapi.amap.com/v3/config/district` | **57** | ✅ 资产二的行政区划列表与中心坐标 |
| 逆地理编码 | `GET https://restapi.amap.com/v3/geocode/regeo` | 878 | ❌ **仅用于坐标系判定与金标准复核，不写入资产** |

> 调用次数取自 `raw_cache.zip` 内 6 个 JSON（去重后的成功响应）。含失败重试的实际 HTTP 请求约 1.6 万次。

## 1.2 地理编码接口的调用方式

```
GET https://restapi.amap.com/v3/geocode/geo
    ?key={KEY}
    &address={地址串}
    &city={adcode 或 "重庆"}
```

| 参数 | 用法 |
|---|---|
| `address` | 物业处：`重庆市{区县}{街道}{小区名}`；房交：`地址`，缺 `重庆市` 前缀时补上 |
| `city` | 传**区县 adcode**（如 `500240`）做区域限定，防止同名地点跨省错配 |

返回 JSON 中取用的字段：

```json
{"status":"1","infocode":"10000","geocodes":[{
   "location":"106.487122,29.565839",   → 经度 / 纬度
   "level":"住宅区",                     → level
   "adcode":"500157",                   → adcode
   "district":"两江新区",                → 高德区县
   "formatted_address":"重庆市两江新区…"  → 规范地址
}]}
```

一条记录有多个候选时，按 `level` 优先级取最优：`住宅区 > 门牌号 > 门址 > 兴趣点 > 单元 > 道路 > 区县`。

## 1.3 行政区划查询接口的调用方式

```
GET https://restapi.amap.com/v3/config/district
    ?key={KEY}
    &keywords={区县名 或 adcode}
    &subdistrict=1
    &extensions=base
```

- 逐个区县拉取其下级区划，返回 `districts[0].districts[]`，每项含 `name` / `adcode` / `level` / `center`
- `center` 即行政区划的行政中心坐标，写入资产二的 `中心经度/中心纬度`
- 高德**不提供街道级边界多边形**（`extensions=all` 时街道的 `polyline` 为空），因此只能用中心点

# 2 资产一：`asset1_poi_coord.csv`

**所有记录的坐标**，一张长表，用 `表` 列区分来源。

| 项 | 值 |
|---|---|
| 行数 | 12,042（物业处 8,782 + 房交 3,260） |
| 可信 | 9,476 / 12,042 = **78.7%** |
| 坐标系 | 全部统一为 **GCJ-02** |
| 采集时间 | 2026-11 |

## 可信判据（两级，缺一不可）

1. **level 可信**：`住宅区 / 兴趣点 / 门址 / 门牌号`
   - 不可用：`乡镇 / 村庄 / 道路 / 区县 / 公交地铁站点`（只到行政单元级）
2. **区县一致**：`高德区县` 与登记的 `区县` 一致
   - 含别名（石柱县 ≡ 石柱土家族自治县）
   - 含等价类（两江新区 ≡ 渝北区 ≡ 江北区）
   - 含功能区代管（高新区 / 经开区 / 双桥经开区 / 万盛经开区 / 北碚部分街道）

另加两条硬过滤：
- 房交面坐标包围盒对角线 ≥ 1000m → 不可信（几何损坏）
- 坐标落在重庆辖区外（105.05–110.45E / 27.95–32.55N）→ 不可信

## 不可信原因分布

| 原因 | 数量 |
|---|---|
| level 不可信 | 1,386 |
| 区县不符 | 1,065 |
| 面坐标包围盒异常 | 113 |
| 坐标在辖区外 | 274（与区县不符部分重叠） |
| 无坐标 | 2 |

> 只查 level 时可信率 84.2%；加区县一致性后降为 78.7%。被剔除的这部分中有 274 条是跨省错配（如 `建银小区`(武隆区) 被解析到新疆伊宁、`福康大厦`(武隆区) 被解析到澳门花王堂区），若直接用于距离判定会污染全部下游结果。

## 字段说明

| `记录ID` | 物业处 = `village_id`；房交 = `愉悦安` |

| `区县` | 登记区县（原始字段，未归一） |

## 使用方式

- **键**：`(区县, 行政区划)`，匹配时对街道名做主干预处理（去"街道/镇/乡/街道办事处"后缀）
- **前缀匹配**：征收处的"街道"字段混有门牌（如 `高阳镇高乐路369号`），取最长可匹配的行政区划前缀
- **父区回退**：高德区划树**没有「渝北区」「江北区」节点**，其 42 个街道挂在「两江新区」(500157) 下，查询时须回退

## 已知局限

1. **中心点 ≠ 辖区范围**：不能做"某坐标是否属于该街道"的点在面内判定；需要该能力须补边界多边形（高德不提供街道级边界）
2. **区划有时效**：永昌街道 2025-12-24 由中山路街道拆分设立；物业处数据（`gmt_create` 2025-11-05）早于拆分，两边都对但时点不同
3. **两个区县节点缺失**：高德无渝北、江北节点，其乡镇（统景镇、兴隆镇）只能用地理编码兜底
4. **覆盖率**：物业处 355 个 `(区县,街道)` 组合 → 100% 命中；征收处 998 个 → 935 同区县命中 + 63 经父区命中，0 未匹配

# 6 金标准的来源与复核

外源坐标除了增强特征，还用于**复核和补全任务 A 的金标准**。本节固化其结论，原始逐条明细不再单独保留。

## 6.1 金标准构成

| 项目 | 数量 | 来源 |
|---|---|---|
| 初始标注 | 2,709 对 | 按「小区名 + 区县」精确一致生成 |
| 外源坐标补全 | 317 对 | 坐标距离判定（同名/异名 + 坐标重合） |
| **合计** | **3,026 对** | |

补全的 317 对按判据分为四类：

| 类型 | 数量 | 判据 | 置信度 |
|---|---|---|---|
| 同名 + 坐标重合 | 206 | 名称完全一致，距离 ≤ 120 m | 高 |
| 同名 + 邻近 | 60 | 名称完全一致，距离 120–400 m | 中 |
| 同名 + 对端已占用 | 36 | 名称完全一致，对端已被另一条房交记录占用（多对一） | 高 |
| 名称变体 + 坐标重合 | 15 | 名称有前后缀/分隔符差异，距离 ≤ 120 m | 高 |

补全后覆盖率：房交侧 82.98% → **92.70%**，物业处侧 30.85% → **32.83%**。

金标准本体存放于 `数据/A_mission_匹配映射_v2.csv`，在原 8 列之外增加 `source`、`confidence`、`distance_m`、`name_sim`、`note` 五列：`source` 区分初始标注与外源补全，`distance_m` 记录坐标距离证据，`note` 记录经复核确认的 87 条对的处理结论。评测时可按 `source` 分层报告。

## 6.2 现有金标准的复核

对 878 条「距离矛盾或偏大」的对逐条做了逆地理编码复核，**结论是 0 条标注错误**，全部为坐标或编码问题：

| 复核结论 | 数量 | 占比 | 成因 |
|---|---|---|---|
| 区县完全一致 | 685 | 78.0% | 物业处正向地理编码跑偏，标注正确 |
| 功能区 ↔ 法定区口径差异 | 106 | 12.1% | 两江新区 ≡ 渝北/江北；蔡家岗、童家溪属北碚但归两江直管 |
| 区县一致、街道不同 | 79 | 9.0% | 街道/镇是**行政单元**而非地名；或区划调整的时点差异 |
| 区县确实不一致 | 8 | 0.9% | 经人工判断，仍有 7 条为坐标不可信、1 条存在真实二义性并被确认保留 |

## 6.3 人工判断记录的两个关键事实

街道冲突的成因有四类，其中两类有具体实证：

**同名异地会导致地理编码错位。** 合川区「凯正四季花都」被高德解析到 **江津区四季花都**（相距 93 km）——同一开发商在不同区县的项目使用了相同案名。这说明即使 `level` 显示为「住宅区」，也必须校验返回区县与登记区县是否一致。

**行政区划存在生效日期，跨时点比对会产生假冲突。** 「万科城二期」的物业处登记街道为「中山路街道」，高德逆地理编码返回「永昌街道」，二者相距约 6 km。实际情况是 **永昌街道于 2025-12-24 由中山路街道拆分设立**，而物业处数据（`gmt_create` 2025-11-05）早于拆分——两边都是正确的，只是时点不同。因此行政区划映射必须标注采集日期，且在跨时点比对时不做强制一致性判定。

## 6.4 口径约定

- 街道/镇/乡**不作为文本特征**使用。它们是行政单元，文本本身不携带地理含义，只用于候选阻断与一致性校验；其地理含义通过资产二的中心坐标获得。
- 区县"一致"包含三类等价：别名（石柱县 ≡ 石柱土家族自治县）、等价类（两江新区 ≡ 渝北区 ≡ 江北区）、功能区代管（蔡家岗街道、童家溪镇属北碚区但由两江新区直管）。缺任一条都会把正确配对误判为冲突。
