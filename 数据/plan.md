# 7.2 主实验：跨源记录链接与拒识

## 1 问题

给定两张异构表与字段映射，在**不使用已有对应关系**的条件下，能否为 A 表每条记录在 B 表中正确检索对应记录，并在对端不存在时正确**拒识**；当**主匹配字段被部分或全部遮蔽**时性能如何退化；**两组外源地理数据**（POI 坐标、行政区划物理位置）各自的贡献是什么；Full Model 的增益来自哪里。

两个任务（A / B）使用**同一套任务定义、指标、评测集构造流程与消融设计**，模型不做任务特化。

## 2 已核实的数据事实

> 每条均由实测得出，是实验设计的依据；与之冲突的旧假设已删除。

| 项目 | 事实 | 影响 |
|---|---|---|
| 规模 | A：物业处 8,782 / 房交 3,260；B：28,101 / 28,101 | A 的候选侧是瓶颈 |
| 金标准 | A：3,026 对（2,709 + 外源坐标补全 317）；B：28,101 对（同行） | A 覆盖 92.70% / 32.83% |
| 名称一致率（A） | 3,014 / 3,026 = **99.6%** | 主字段可用时 A 近乎满分 |
| 名称变体（A） | 仅 **15 条**（0.5%） | "跨源异名消歧"不是难点 |
| 标注错误（A） | **0 条**（878 条可疑对逐条复核） | 金标准问题在不完整，不在错 |
| 坐标系（A） | 房交 = CGCS2000/WGS84，高德 = GCJ-02 | 距离计算前必须 `wgs2gcj` |
| 字段同值率（B） | 11 对字段中 **9 对 100% 同值**，地址同值率 100% | B 预期接近饱和 |
| 天然无对端 | A：物业处 **5,899** 条；B：**0** 条 | B 拒识集需按同流程构造 |

**不再做的事**：不把 `小区名+区县` 当键；不把 `物业公司`（A 侧物业处 100% 空）、`lng/lat`（原始全空）当信号。

## 3 两组外源地理数据

### 3.1 资产一：POI 地理编码坐标

用高德**地理编码 API**（`GET /v3/geocode/geo`）把记录描述的地点解析为坐标——**不是关键字搜索**（`place/text` 个人认证仅 5,000 次/月，8,782 条无法完成；地理编码配额 150,000 次/月）。

| 项 | 内容 |
|---|---|
| 输入 | 物业处：`重庆市{区县}{街道}{小区名}`；房交：`地址`（必要时补 `重庆市` 前缀） |
| 输出 | `(lng, lat)`、`level`、`adcode`、`district`、规范地址串 |
| 覆盖 | 物业处 8,782 条 **100%** 有坐标返回；房交 3,260 条由面坐标质心得到 |
| 坐标系 | GCJ-02；房交原始的 `面坐标` 为 CGCS2000/WGS84，须先 `wgs2gcj` |
| **可信** | 合计 **9,476 / 12,042 = 78.7%**（物业处 6,329 / 72.1%，房交 3,147 / 96.5%） |

**可信必须两级判据，只查 level 不够**：

| 判据 | 规则 |
|---|---|
| ① level 可信 | `住宅区 / 兴趣点 / 门址 / 门牌号` 可作位置证据；`乡镇 / 村庄 / 道路 / 区县 / 公交站` 只到行政单元级，不可用 |
| ② 区县一致 | 高德解析出的区县 必须与登记区县一致（含自治县简称、两江≡渝北≡江北、功能区代管） |

**为什么必须加第②条**（物业处 2,453 条不可信的成因）：

| 原因 | 数量 | 例子 |
|---|---|---|
| level 不可信 | 1,386 | 只定位到乡镇/村庄/道路/公交站 |
| **区县不符** | **1,065** | `六福苑`（江北区）→ 沙坪坝区大石坝镇；`建银小区`（武隆区）→ **新疆伊宁市**；`福康大厦`（武隆区）→ **澳门花王堂区** |
| 坐标在重庆辖区外 | 274 | 含跨省、跨市错配 |
| 无坐标 | 2 | — |

只查 level 时可信率为 84.2%，加上区县一致性后降到 **78.7%**——被剔除的 5.5 个百分点里有 274 条是跨省错误（新疆、澳门、广东、江西），若直接用于距离判定会污染全部下游结果。

不可信的坐标保留在资产中并标注原因，但**不参与距离判定、不作为边、不进特征**。

### 3.2 资产二：行政区划 → 物理位置

**背景**：`街道`/`镇`/`乡` 是**行政单元**，不是地名。作为文本 token 它不携带任何地理含义——"中山路街道"这四个字不会告诉模型该小区在哪里，只会让两个恰好同属一个街道的小区在字符 n-gram 上假性相似。

**做法**：把每个行政区划解析为它的**中心坐标**。

| 项 | 内容 |
|---|---|
| 来源 | 高德**行政区划查询 API**（`GET /v3/config/district`），逐区县拉取下级区划，取 `center` |
| 规模 | **1,094 条**街道/镇/乡，覆盖 40 个区县，全部带中心坐标 |
| 键 | `(区县, 街道名)`；街道名做主干匹配（去"街道/镇/乡/街道办事处"后缀） |
| 覆盖 | 物业处 **100%**（8,782）、征收处 **100%**（28,101） |
| 兜底 | 高德区划树缺失的（如渝北区统景镇、兴隆镇），用地理编码补中心点 |

**已知的区划数据问题**（须写入论文）：

| 现象 | 说明 | 处理 |
|---|---|---|
| 功能区覆盖法定区 | 高德区划树中**无「渝北区」「江北区」节点**，其 42 个街道全部挂在「两江新区」(500157) 下 | 查询时对渝北/江北/北碚启用父区回退 |
| 部分街道由功能区代管 | 蔡家岗街道、童家溪镇行政属北碚区，实际由两江新区直管 | 同上 |
| 区划有时效 | 永昌街道 2025-12-24 由中山路街道拆分设立；物业处数据（`gmt_create` 2025-11-05）早于拆分 | 映射表须带生效日期，比对时按数据时点 |
| 字段粒度不一致 | 征收处的"街道"字段混入门牌（如「高阳镇高乐路369号」） | 前缀匹配 |

### 3.3 两组数据的语义差异

这是不能混淆的核心：

| | 资产一：POI 坐标 | 资产二：区划中心坐标 |
|---|---|---|
| 描述对象 | 一个**具体地点**（小区 / POI） | 一个**行政单元**（街道 / 镇） |
| 精度 | 10 ~ 100 m | 1 ~ 10 km |
| 覆盖 | 84.2% 可信 | 100% |
| 语义 | "这个小区在这里" | "这个小区属于这个行政单元" |
| 主要作用 | **精确定位、距离判定** | **粗定位、候选阻断、一致性校验** |
| 误用后果 | — | 把它当精确定位会引入千米级误差 |

### 3.4 两组数据进入模型的位置

| 环节 | 资产一（POI 坐标） | 资产二（区划中心） |
|---|---|---|
| **特征层** | 追加 `(lng, lat, level_可信)` 数值特征；原 `区县`/`街道` 文本 token 从序列化串中移除 | 追加区划中心 `(lng, lat)` 两个数值特征 |
| **图结构** | `geo_near` 边：两侧坐标距离 < 阈值 | `same_admin` 边：同区划单元 |
| **候选生成** | 地理网格阻断（2km 网格 + 相邻 8 格） | 区县/区划做一级粗筛 |
| **负采样** | 按**距离分档**：<100m 极难 / 100–300m 难 / 300–1000m 中 / >1000m 易 | 按区划内/外分层 |
| **拒识** | 距离 + level 可信度作为拒识依据 | 区划一致性作为辅助校验 |
| **消融** | E4：关掉 POI 坐标，只用区划中心 | E1：关掉区划中心 |

### 3.5 三条硬约束

1. **只做增强，不提供标签**：外源数据不得用于反推任何金标准对端，也不得用测试标签筛选。
2. **离线快照 + 采集日期**：全部原始 API 响应落盘为 `数据/外源数据/raw_cache.zip`，标注采集日期（2026-11）、坐标系（GCJ-02）、许可与配额消耗。
3. **不可用即不用**：level 不可信的坐标不参与距离判定，宁可标 `unresolved`。

## 4 统一任务定义

### 4.1 任务（两任务共用）

给定 `(表 A, 表 B, 字段映射)`，为 A 中每条记录在 B 中输出对应记录集合 `S`：`S = ∅` 表示**拒识**，`|S| ≥ 1` 表示**链接**。不假设 1:1。

### 4.2 两个任务的实例化

| 项 | 任务 A | 任务 B |
|---|---|---|
| Query 侧 | 物业处 8,782 | 征收处 28,101 |
| 候选侧 | 房交 3,260 | 奥格 28,101 |
| 关系形态 | 多对一（平均 1.05，最多 5） | 一对一 |
| 主匹配字段 | `小区名` ↔ `小区名` | `征收处_房屋地址` ↔ `fwxxdz` |
| 天然拒识样本 | 5,899 | 0（按 §5.1 流程构造） |
| 结构信号 | 坐标、区划、等级、类型、公司 | 坐标、区划、层数、年份、用途、材料 |

### 4.3 主字段遮蔽率：统一控制变量

按比例 ρ 随机遮蔽"主匹配字段"（字段由配置指定，模型代码不变）：ρ ∈ {0, 0.3, 0.6, 1.0}，对应 S0–S3。

### 4.4 任务 B 的定位

B 不做特殊处理，照常运行完整流程与指标。因两源字段高度同值，**预期接近饱和**——该结果用于说明同一协议在不同数据上都能跑通，且 B 的饱和反映数据同源程度而非模型能力。附加报告 B 的字段级同值率、格式差异与缺失模式。

## 5 评测协议（两任务共用）

    ### 5.1 评测集构造

| 类别 | 构造规则（A、B 相同） |
|---|---|
| 正例 | 金标准中的 query |
| **强负例** | 无对端的 query，且候选池内存在空间/结构上邻近的候选 |
| 弱负例 | 无对端的 query，且候选池内无邻近候选 |
| 排除 | 邻近但正负未定 |

- **A**：强负例 2,459、弱负例 2,853、正例 2,822，可评测 **8,134** 条。
- **B**：无天然无对端，从候选侧按 10% 留空生成，再按同规则划分。**流程与 A 一致，仅负例来源不同**，须注明。

### 5.2 指标

链接 P/R/F1（**集合级**，非 Hit@K）；**拒识准确率**（强、弱负例分别报）；端到端集合比对；覆盖率-精度曲线（P@90% 覆盖）；退化曲线（随 ρ）。

原 `utils.评估指标` 中 `P = R = Hit@K` 的定义须废弃。

### 5.3 划分

按 query 侧实体分组，同一实体的所有候选不跨 train/val/test；区县分层；5 个种子，报告均值 ± 标准差。

### 5.4 基准（已实测，作为下界）

**任务 A**

| 条件 | P | R | F1 | 拒识准确 |
|---|---|---|---|---|
| 距离阈值 300m | 0.489 | 0.833 | 0.616 | 0.537 |
| 距离 + 等级 + 类型（规则） | 0.836 | 0.631 | **0.719** | 0.934 |
| 距离 + 主字段可用（参考上限） | 1.000 | 0.829 | 0.907 | 1.000 |

## 6 方法与对照

同一任务、同一划分、同一评测集、同一输出协议。

| 方法 | A 的信号 | B 的信号 | 回答的问题 |
|---|---|---|---|
| 主字段精确匹配 | 小区名 | 地址 | 主字段可用时的参考上界 |
| 距离阈值 | POI 坐标 | POI 坐标 | 位置信号的裸下界 |
| 距离 + 枚举字段规则 | 坐标+等级+类型 | 坐标+层数+年份+用途 | 不用图结构的上界 |
| TF-IDF Cosine | 同一序列化文本 | 同上 | 纯语义相似度的贡献 |
| 原始 LightGCN | 标签边+基础节点/边 | 同上 | 收益是否来自图流程本身 |
| **Full Model** | F2S2G + POI 坐标 + 区划中心 | 同机制 | 总体效果 |
| Full Model（关外源） | 仅区划中心，无 POI 坐标 | 同机制 | 区分图框架 / 外源知识收益 |

**消融**（两任务各跑一遍）：E1 去区划中心特征；E2 去等级/类型辅助边；E3 负采样改随机；E4 关 POI 坐标仅用区划中心；E5 ρ=0 对照。另加 **E6：POI 坐标按 level 可信/不可信分组报告**，量化外源精度的贡献。

## 9 边界与风险

1. **A 的提升空间有限**：ρ=1 时规则上限 0.719，主字段可用时 0.907；模型可争取区间约 0.72 → 0.78。
2. **B 预期接近饱和**：两源 9/11 字段同值，F1 可能接近 1.0；价值在于验证协议可迁移。
3. **B 的拒识集是构造的**：从候选侧留空生成，与 A 的天然负例不同源，须明示。
4. **拒识标签的构造使用主字段**：强负例以"主字段相似度 < 0.3"界定，而模型在 S3 下看不到主字段，存在信息不对称——这是设计意图，须明示。
5. **区划中心不等于辖区范围**：它只是一个点，不能表示"某坐标是否属于该街道"；若需点在面内判定，须补充边界多边形。
6. **外源数据有时效**：区划有生效日期，须记录采集日期（2026-11）并离线快照。
7. **结论限定范围**：不支持"图神经网络显著优于基线"的强断言；可支持的断言是"主匹配字段缺失时的链接与拒识能力"，以及"同一协议可迁移到第二个异构任务"。

## 10 可复现性

- 固定种子；`数据/外源数据/raw_cache.zip` 保存全部原始 API 响应与抓取日期；
- 区划映射、POI 坐标、金标准 v2、两任务评测集均版本化；
- 字段白名单/黑名单、主匹配字段、遮蔽率、外源数据接入开关写入配置，不写在代码里。
